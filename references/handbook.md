# 半导体行业每日晨报 · 执行手册

> 本文件是晨报的**主流程与硬性规则**。修改本文件即修改每日行为，无需改动调度。
> 配套文件：`watchlist.md`（产品/标的映射）、`report-template.md`（Word 八章骨架）、`output-spec.md`（投递规格）。
> 路径以 `config.json` 为准：`{report_dir}`、`{docx_basename}`、`{recipient}`、`{timezone}`。

## 0. 核心原则（最重要，先读）

**这份晨报的主轴是“产品”，不是“盘面”。**

1. **产品优先**：优先收录**新产品、新工艺节点、新型号、新规格、客户导入、量产/良率、涨价/缺货的具体型号**。一条“公司发布新品”的公告如果写不出型号、规格、客户、时间，就不要收录。
2. **主流看法做验证**：每期必须给出“主流怎么看”——卖方研报的一致预期、产业界（台/韩/欧美供应链、SEMI/WSTS 等）的主要判断、以及**共识之外的分歧点**。避免只罗列“某券商看好”。
3. **盘面只做背景**：指数涨跌、资金流向、解禁回购等只在影响产品逻辑时出现，且放在最后或作为风险项；不要占据报告主体。
4. **落到 A 股**：每条产品新闻都要回答“利好/利空哪个环节、哪几只票、传导要多久”。

## 1. 执行前检查

1. `date` 确认时间，按 `{timezone}` 解释报告日期（默认 Asia/Shanghai）。
2. 覆盖窗口：**前一日 `window_start` → 当日 `window_start`**（默认 05:00 → 05:00）。窗口外仍在发酵的产品/技术事件可收录，须注明原始时间。
3. 判断是否为交易日（周末/节假日 → 顶部标注“今日休市”，产品内容照常）。
4. 读取 `watchlist.md` 的“产品/技术跟踪矩阵”，确定本期要核对的节点与型号。
5. 确认 `{report_dir}` 存在且可写；规则文件（本手册、清单、模板）每次重新读，不要凭记忆。

## 2. 检索（并行，产品维度优先）

用 `web_search` 一次并发 5–6 组查询，顺序按重要性：

| 组 | 查什么 | 查询示例 |
|---|---|---|
| A 先进制程/封装 | N2/N2P/A16、CoWoS/SoIC/CoPoS、混合键合、CPO、背面供电 | 「台积电 2奈米 A16 量产 良率」「CoWoS 产能 2026」「混合键合 国产 设备」 |
| B 存储产品与价格 | HBM4/HBM3E、DDR5/DDR4 合约价、NAND、原厂产能与良率 | 「HBM4 量产 占比」「DDR5 合约价 上涨」「美光 SK海力士 产能」 |
| C 算力芯片与终端 | 英伟达 Rubin/GB、昇腾、寒武纪、海光、AI 手机/折叠屏/汽车芯片 | 「英伟达 Rubin HBM4」「昇腾 寒武纪 涨价」「AI 加速卡 缺货」 |
| D 设备与材料产品 | 新品发布、客户验证、订单/中标、收购、国产化率 | 「北方华创 中微 新品」「半导体设备 验证 客户」「湾芯展 新品」 |
| E 主流看法 | 券商研报、产业界预测、一致预期与分歧 | 「存储 超级周期 券商」「SEMI WSTS 预测」「摩根 台积电 观点」 |
| F 事件日历 | GTC、法说会、财报（泛林/应材/台积电）、韩国出口、展会 | 「下周 半导体 事件 财报」「GTC 黄仁勋 演讲」 |

- 目标：**8–12 条产品级信息 + 3–5 条主流看法**。宁可少而硬，不要凑宏观。
- 对关键产品信息用 `web_fetch` 核对**规格参数、时间点、客户**，并确认**发布时间**。
- 台/韩/欧美媒体（MoneyDJ、中时、newsis、TheElec、首尔经济）常有一手产品信息，优先采信并注明出处。

## 3. 分析（每条产品新闻五问）

1. **产品**：什么型号/节点/规格/封装形式？和上一代差多少（性能、功耗、密度、容量、价格）？
2. **进度**：研发/送样/验证/小批量/量产/放量，卡在哪（良率、设备、材料、客户认证）？
3. **供应链**：谁供货、谁受益、谁被替代？国产化率变化？
4. **价格**：是否涨价/缺货？涨幅与时间窗口？
5. **落到 A 股**：利好/利空哪个环节、代表标的（带代码）、传导时效（当日/1–2 周/中期）。

**主流看法部分必须做到：**

- 至少 **3 家机构 + 1 个产业界口径**；
- 每条标注性质：**共识 / 分歧 / 新变量**；
- 给出一句判断：“市场目前 price in 了什么、还差什么”。

## 4. 质量红线

- 产品信息必须到“**型号/节点/规格**”层面，禁止只写“发布新品”“技术领先”。
- 每条事实必须带**来源链接 + 发布时间**。
- 区分：**已发生事实 / 机构预期 / 未证实传闻**（传闻标“未经证实”）。
- 不编造参数、价格、客户、代码；拿不准就写“待确认”。
- 检索失败如实写入“检索异常”，不臆造补位。

## 5. 产出与投递（邮件，本地不留备份）

### 5.1 生成深度版（临时文件）

- 路径：`{report_dir}/{docx_basename}YYYY年M月D日.md`（临时，发送后删除）
- 结构严格按 `report-template.md` 的**八章**。
- 不要用 `present` 之类工具额外生成副本（本地不留文件）。

### 5.2 转 Word 附件（命名规则固定）

附件名 = **`{docx_basename}` + 年月日**，不补零，例如 `半导体晨报2026年10月9日.docx`。

```bash
D=$(date +%Y年%-m月%-d日)   # 2026年10月19日
python3 scripts/md2docx.py "{report_dir}/{docx_basename}$D.md" "{report_dir}/{docx_basename}$D.docx"
```

（`scripts/md2docx.py` 为无依赖的 OOXML 生成器，不需要 pandoc / python-docx。）

### 5.3 发送邮件

- 收件人：`{recipient}`（`config.json` 的 `recipient`）
- **正文 = 精简版**（按 5.5 的 200–300 字/条规格，纯文本、无 Markdown 符号残留）
- **附件 = Word 深度版**
- 发送方式取决于 `delivery.mode`：
  - `dsh_tool`：调用 DSH 的 `send_email` 工具，示例：
    ```
    send_email(
      to=<config.recipient>,
      subject=<按 config.subject 渲染，例如 "半导体晨报 · 2026-10-19">,
      body=<精简版正文>,
      attachments=[<report_dir 下的 docx 绝对路径>],
    )
    ```
  - `smtp`：`python3 scripts/send_email.py --config config.json --subject … --body-file … --attach …`（密码从环境变量读）
  - `none`：只生成文件，不发送
- **主题不要自带邮件插件的前缀**：例如 DSH 的邮件插件会自动加 `subjectPrefix`（默认 `[DSH]`），自己再加会变成 `[DSH] [DSH] …`。
- 发送失败（工具返回失败或附件缺失）→ **不要删除本地文件**，在会话里说明失败原因并保留文件供重试。

### 5.4 清理（硬性要求）

发送成功后立刻删除本地副本，**不保留任何报告备份**：

```bash
D=$(date +%Y年%-m月%-d日)
rm -f "{report_dir}/{docx_basename}$D.md" "{report_dir}/{docx_basename}$D.docx"
```

`{report_dir}` 只作为发送前的临时工作区；规则文件、模板、脚本属于工具链，保留。

### 5.5 邮件正文（精简版）规格

**每条要点 200–300 字**，整篇 1500–2500 字，直接可读、不靠表格压缩信息。结构：

1. `📅 半导体晨报 · YYYY-MM-DD`（休市标注）
2. 一句话总览（今天最该知道的产品级变化）
3. **3–5 条产品要点**，每条 200–300 字，固定写全六要素：**型号/节点 → 关键参数 → 进度 → 卡点 → 供应链影响 → A 股落点（标的+时效）**
4. **主流看法**：分“共识 / 分歧 / 新变量”三段，每段 150–250 字，点名机构与判断
5. **映射表**（4–7 行）：环节｜方向｜标的｜产品逻辑｜时效
6. 本周产品事件（GTC/财报/出口数据）
7. 邮件说明（附件为 Word 深度版）+ 非投资建议声明

> 允许长。信息密度优先于篇幅；但禁止用套话填充——每句话都要有具体信息（型号、数字、机构、时间）。

## 6. 异常处置

| 情况 | 处理 |
|---|---|
| 某组查询无产品级新增 | 宁可写“本期无重大产品更新”，不拿宏观凑数 |
| 抓取失败 | 换一家同题报道；仍不成 → 记录“检索异常” |
| 只有股价异动、无产品原因 | 不单列，最多作为风险提示一句 |
| 产品信息互相冲突 | 并列双方来源（如韩媒 vs 台媒），标注分歧 |
| 用户当天已手动要过一份 | 重新检索最新数据，不复用旧文档 |

## 7. 结尾必须附

```
> 本报告由公开信息自动整理，不构成投资建议。产品参数与价格请以厂商公告为准。
```
